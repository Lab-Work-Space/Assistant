## 1. Defect
**DEFECT-001 Critical, owner backend.** Approving (or deleting) a lesson with the real `SettingsService` deadlocks forever and holds the single DB lock (the whole app freezes).
- `core/growth/lessons.py:194` (`on_decision`, inside `db.transaction()`) -> `core/growth/overlays.py:76` `rebuild` -> `overlays.py:16` `max_chars` -> `core/settings/service.py:67` `settings.get` -> `db.fetchval` -> `core/db/sqlite.py:197`, waiting on the lock that the open transaction already holds (`sqlite.py:201-204` documents "self.* deadlocks"). `delete()` (`lessons.py` rebuild call) takes the same path.
- `except Exception` in `max_chars` cannot catch it: no exception is raised, the await never returns.
- Hidden from unit tests: `tests/test_growth_lessons.py` `Settings` wrapper serves `growth.overlay_max_chars` from a dict, never the DB.
- Repro (fails today): `no_proxy='*' PYTHONPATH=. .venv/bin/pytest -q -o faulthandler_timeout=30 tests/acceptance_growth -k defect001` (TimeoutError after 5 s).
- Fix direction: read the cap before opening the transaction and pass it into `rebuild`.
- The other e2e tests use fixture `nodeadlock`, which patches `max_chars` to 3000 so downstream behaviour could still be verified.
