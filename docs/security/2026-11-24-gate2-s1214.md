## Findings
### G2S1214-01 (Low, FIXED in audit) — line forging through Unicode line separators
`_clean` folded only `\n` and `\r`. `ensure_ascii` escapes U+2028/U+2029/U+0085, `\v`, `\f` and bidi controls on disk, but `json.loads` in `format_line` turns them back into raw characters. Probe: `error="c d‮X"` was forwarded raw. Some Discord clients render U+2028 as a line break, and U+202E can visually reorder a line. This broke the Gate 1 residual's claim that a value "cannot add new lines". Fix: `_FOLD` maps each line separator to a space and each bidi control to `?`, one for one, so existing lengths and `\n`/`\r` output stay the same. A re-probe gave `error=a b   c?X Y`. Owner: tester, who should add a regression vector to `test_s1214_02_forward_keys_only` or A2 (tests were not edited in this audit).

### G2S1214-02 (Info) — forwarder task outlives a late System failure
If `system.start` raises after `_system_ready` succeeded, `_system_failed` clears the queue and the tap but does not cancel `_fwd_task`. With no tap, nothing new is queued, so the task idles until `shutdown`. Optional: cancel `_fwd_task` in `_system_failed`. Owner: backend.

### G2S1214-03 (Info) — `by` / `reason` / `user` in FORWARD_KEYS
Current WARNING+ sources pass codes (`reason="origin"`, `reason=code.split(...)`), ids (`user=uid`) or `actor.ref` (`approval.denied by=`). None of them is free text a human typed. Any future free text falls under the accepted residual: one line, 64 chars, masked, no mentions.
