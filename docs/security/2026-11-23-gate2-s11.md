## Fixed in this audit
Each fix is one spot in one file. Narrow tests passed, then the full suite: 236 passed.
- **F-1** `deploy/install.sh`: `cd /` after the root check. `python -c` (DAVE gate) put root's cwd on `sys.path`, so a `discord.py` planted in the caller's directory would have run as root.
- **F-2** `core/db/backup.py` `restore`: unlinks the live `-wal`/`-shm` **before** `os.replace`, as S11-01 requires. Before the fix, a crash between the swap and the unlink could replay the old hot WAL into the restored DB, which is most likely on the `--allow-optout-gap` path.
- **F-3** `core/db/backup.py` `__main__`:
  - `sqlite3.Error`/`OSError`/`ValueError` now print `backup_error:<Type>` and exit 2, instead of a traceback (rule 16);
  - `TASKS_RETENTION_DAYS` must be within 1..3650 (0 would have deleted every finished task).
- **F-4** `core/migration/__main__.py`: the same type-only handling (`migration_error:<Type>`), so a failing `ExecStartPre` writes no traceback to the journal. `core/migration/retention_main.py` now also catches `OSError` (rule 8 sibling).
- **F-5** `docs/helper/setup.md` §8.5: `cd /opt/employee/app` before the restore commands. `python -m core…` imports from the cwd, so the commands failed outside the app dir and would have imported a planted `core/` package from any other directory. The Contents line numbers were updated.
- **F-6** `deploy/install.sh`: `status --porcelain --untracked-files=all`. Before the fix, untracked files, which `python -m` would import from `WorkingDirectory`, passed the clean-tree check.
- **F-7** `tests/test_ignore_files.py`: `test_gitignore_keeps_sources` checks that sources, the lock, `.env.example` and `knowledge/meetings/.gitkeep` are not ignored (rule 19).
