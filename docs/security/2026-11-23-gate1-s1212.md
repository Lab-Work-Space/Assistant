## Findings
Severity uses CVSS-style labels. "Merge" means before the TASK-016 merge (or TASK-002 where named). "Live" means before `VOICE_ENABLED=true` on the VPS.

**S1212-01 — Medium — §12.12.6 step 4, §12.12.9 — consent_gap check fails open (merge).**
`os.path.exists` never raises: it returns False on EACCES and on a dangling symlink. The "or raises → fail closed" branch can never fire, so an unreadable marker means capture is allowed.
Change: one shared helper `consent_gap_present(db_path) -> bool` (in `core/db/backup.py`, beside the writer) does `os.lstat(marker)`. `FileNotFoundError` returns False. Any other `OSError` returns True. Live record and upload both use it. Tests: parent directory mode 000, a dangling symlink at the marker path, and a regular file.

**S1212-02 — Medium — §12.12.6 step 8, opt-out steps 2–4 — opted-out audio can still reach Google (merge).**
The worker checks `allowed` only after the STT call returns. A chunk swapped to the queue before an opt-out (or before `/voice record stop`) is still sent to Google, even though the result is discarded.
Change:
- Step 8 re-checks `uid in session.allowed` (under the lock) immediately before building the request, and skips the chunk otherwise.
- Opt-out steps 2 and 3 run without an `await` between them. The in-memory removal happens before the DB upsert, so a DB error still keeps the user out for the session.
- test_consent adds a case: a chunk queued, then the user opts out, then no STT call is made for that chunk.

**S1212-03 — Medium — §12.12.12 Triggers, `core/interfaces.py` `VoiceHooks.after_reply`, `core/gate/reply_gate.py` "after_reply(m.guild.id if m.guild else None" — TTS speaks text to people who cannot read it (merge).**
The hook carries no channel id. Any reply to a user who is in Praw's voice channel gets spoken aloud there, including replies in private allowlisted channels and DM replies (guild None). Everyone in the voice channel hears it.
Change:
- Add `channel_id: int` to `VoiceHooks.after_reply` (additive). Return early when `guild_id is None`.
- Speak only when `channel_id == vc.channel.id` (the voice channel's own text chat).
- Apply `mask_secrets` to the text before `strip_markdown`: `res.text` is unmasked at the hook (masking happens at send).
- Test: a reply in another allowlisted channel and a DM reply are both silent.

**S1212-04 — Medium — §12.12.8 Sanitising and prompt change, `store.py` `erase_user` "if ln.startswith(\"## \")" — erasure bypass through `## ` lines (merge).**
`erase_user` treats every line starting `## ` as a section header and always keeps it. Two consequences:
1. A display name such as `## Bob` makes that user's transcript line a header line, and `erase_user` keeps it.
2. Model output containing a `## X` line, through STT-driven prompt injection or plain model drift, ends the Summary section early. Every summary line after it then survives erasure, because the model never sees user ids.

Change:
- The display-name sanitiser also strips leading `#` and whitespace.
- The system rewrites every model-output line whose left-stripped form starts with `## ` to `### `.
- STT text and display names fold every `str.splitlines()` separator (`\r \n \v \f \x1c-\x1e \x85    `) and all Cc characters to spaces, not only `\r\n`. The index and search paths use `splitlines()`.
- test_note adds cases: a name `## Summary`, model output with `## Participants` in the middle, and a ` [1]:` in STT text.

**S1212-05 — Medium — §12.12.6 Late joiner step 2 and happy path step 2 — the notice content may not reach the joiner (merge; mitigation within the OQ-18 decision).**
A jump link to the main notice shows nothing to a member without Read Message History in that channel. The late-joiner line is then a ping with no disclosure.
Change:
- The late-joiner message carries the full G1-12.2 disclosure text (provider, members-only note, 90-day retention, `/voice optout`, erasure). The jump link is extra.
- If the main notice post fails, capture never starts: refuse with a new code `notice_failed`, end the session as failed, and post an admin line. Today the spec states this only for late joiners.
- The TASK-021B-V probe adds a member without Read Message History.
- Optional, recommended: the main notice also mentions the members present at start (`AllowedMentions(users=present)`), under the same exception as S1212-09.

**S1212-06 — Low/Medium — §12.12.9 Validation — the upload cap can be raced and timeouts are uncounted (merge).**
The daily cap counts `usage_events`, which are written only after Google responds. Concurrent `/voice transcribe` calls by one user all pass the count, and timeouts never count. Each attempt costs up to 14 MB in memory (×≈3 with base64 and SDK copies) plus a paid call. Any member can trigger this.
Change:
- Keep a process-wide in-flight upload limit of 1 (reply `voice_busy`) and one per user.
- Reserve the attempt before download: insert the `usage_events` row with `units=0` and the final `ref`, and update it after the response, so failures and timeouts count.
- Re-check `len(data) <= VOICE_UPLOAD_MAX_MB` after `attachment.read()`.
- Never log or echo `attachment.url` (a signed URL) or `attachment.filename` (it may contain personal data). Replies are ephemeral.

**S1212-07 — Low — §12.12.6 ConsentSink (PASTE VERBATIM) — per-speaker buffer is unbounded if the flusher stalls (merge).**
`write` appends on the router thread with no byte cap (global rule 10). A stalled flusher, for example while the event loop is blocked, grows buffers without limit.
Change: in the verbatim block, after taking the lock, `if len(buf) >= s.max_buf: return` with `max_buf = 2 * VOICE_CHUNK_S * 32000`. Audio dropped this way becomes a gap marker. Rule 29 check: the block imports only `discord` and `core.voice.pcm`, and no ownership rule forbids `core/voice` from importing discord. OK.

**S1212-08 — Low — §12.12.6 Button router / opt-out — click semantics are not stated (merge).**
Change:
- The opt-out and opt-in handlers act only on `interaction.user.id`. The user must be a guild member (fail closed). The handlers take no target from the custom id.
- A click on a `status='done'` (re-ask) row only upserts or deletes `voice_optouts`. It never changes another session's `allowed`.
- Step 4 reads "non-bot present members".

**S1212-09 — Low — §12.10.1 S1210-05 — the mention exception is recorded only in §12.12.19 (merge).**
Change: edit the S1210-05 bullet to list "late-joiner consent mention: `AllowedMentions(users=[uid], everyone=False, roles=False)`", plus the present-members notice if S1212-05's option is taken. Test: the late-joiner send has exactly that AllowedMentions.

**S1212-10 — Low — §12.12.6 step 4 re-ask, §12.12.12, `pcm.py` — robustness of fixed paths (merge).**
- **Re-ask notice:** limit to one post per channel per 10 min. While the marker exists, any present member can repeat `/voice record start` and spam notices.
- **TTS rate:** restrict it to the set {8000, 12000, 16000, 24000, 48000}. Today `48000 % rate == 0` alone admits rates where `960 % k != 0`, for example rate 960 or 75. These give wrong frame sizes or a `frombytes` ValueError in the py-cord player thread.
- **TTS size:** cap the TTS PCM at `TTS_MAX_CHARS * 4800` bytes. Anything larger gets `tts_format_unsupported`.
- **Opus load:** on Linux, load `libopus.so.0` directly. `ctypes.util.find_library` spawns `ldconfig`/`gcc` through PATH.

**S1212-11 — Low — §12.12.3, §12.12.10 — handling of the STT key and its errors (merge).**
- `GOOGLE_STT_API_KEY` enters the masking exact set and the short-secret startup refusal (global rule 30) whenever it is set, not only when `VOICE_ENABLED`.
- `CloudStt` maps `HTTPError` and `URLError` to fixed codes and never logs the response body, which may hold transcript text.
- The STT segments fed to the note use the existing `core/agents/untrusted.py` `wrap_untrusted`, not ad-hoc tags.

**S1212-12 — Medium — native decode of untrusted packets (live; accepted residual with conditions).**
libopus0 and `davey` decode attacker-controlled RTP inside the process that holds every bot token. This conflicts with global rule 4 (untrusted media parsed in a secret-free process). Splitting the process is out of proportion for phase 1, so this is accepted with conditions:
- libopus0 is covered by Debian security updates (unattended-upgrades origin check, as in §11.19).
- The service restarts after a libopus or davey update.
- The B2-PKG step records `dpkg -l libopus0` and the davey wheel version in the deploy report.
- The G2S11-02 binary scan covers both.

**S1212-13 — Low — §12.12.17 strings, §12.12.19 — notice and spec wording (live).**
- The notice must not say audio is "discarded" by Google. Say "sent to Google (Gemini API / Cloud Speech-to-Text) for transcription under Google's API terms, outside Thailand". The "held in memory" claim applies to our system only.
- §12.12.19 should say that opted-out audio is decoded by py-cord in memory but never stored or sent. It should not suggest the audio is never processed.
- The status embed in the voice text chat carries only the status and the note path, never the hook or summary.

**S1212-14 — Medium — data terms and spike data (live; TASK-002 conditions before the probe runs).**
- **Owner confirms Gemini paid-tier terms (OQ-19)** for the Google project behind `GOOGLE_API_TOKEN`: billing enabled, so prompts are not used for product improvement. Record this in docs/helper/setup.md. On the free tier, the notice text is false.

- **TASK-002 recordings:**
  - opt-in participants only;

  - confirm that `~/Desktop` is not synced to iCloud, or write outside it;

## Accepted residuals
- Uploads rely on the uploader's assertion and can only be erased whole (stated in the notice and reply). These are owner decisions.

- Audio of opted-out speakers is decoded transiently by py-cord before `write` filters it.
- The upload goes to Gemini inline. Google-side retention follows the API terms (S1212-14).
