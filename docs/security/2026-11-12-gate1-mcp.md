# Gate 1: R6 MCP-1

Verdict: **CONDITIONAL_APPROVE**. The shape is right. It uses stdio only, with one fresh `--network none` container per call. The image is pinned by id, nothing holds a secret, the protocol client is our own and capped, and the hash is re-checked before every call. Every result taints the run, write class always gets a human card, and the switch defaults to off. Before BE1 starts, the spec must be amended with MC-C1 to MC-C9. MC-C10 to MC-C19 bind the build and are checked at Gate 2.

Code is cited by content anchor. Line numbers are hints taken at HEAD `3a5bb01`.

## What was verified (no condition needed)

- **PM-C12 scoped exception (spec §5.1, §7.2): accepted.**
  - Today `classOf` is `map.get(name) ?? FAIL_CLOSED` (tools/manifest/catalog.ts `buildCatalog`, "classOf: (name: string): ToolClass => map.get(name) ?? FAIL_CLOSED").
  - V3 ("V3: a name may not start with") keeps every static name out of `mcp_`, so `map.get` can never shadow an external name.
  - `MCP_NAME` is anchored and has no `m` flag. JS `$` does not match before a trailing `\n`.
  - The profile comes only from the admin's `class` field. A server name lands in the `<tool>` part only after normalization (§5.2). Fullwidth or uppercase lookalikes fail the regex and get FAIL_CLOSED.
  - The slug has no `_`, so a name parses one way only.
  - Both profiles are `sensitive:true`. So `isNonSensitiveTool` (discord/approval/approval-rooms.ts) is false for every `mcp_` name, which means:
    - the card stays in #setting;
    - it is never batched (B7);
    - skill grants refuse it (tools/skill-grant.ts);
    - the AI approver returns `hard_deny:sensitive` (governance/ai-approver.ts, "if (!isNonSensitiveTool(name)").
  - `MCP_WRITE.autopilot='always_card'`: autopilot `decide` checks `isAlwaysCard` before anything else (governance/autopilot.ts "if (isAlwaysCard(r.tool)) return CARD").
  - Write class in a direct, untainted praw chat:
    - `approvalFor` returns false (tools/policy-approval.ts "ctx.direct && !ctx.tainted()");
    - but the tool's own `{reason}` is truthy, so `approval = central || own` is still a card (tools/registry.ts `exec`);
    - the tree grant needs `own === false`;
    - `waivable` needs `own === false` or AUTOPILOT_OWN_WAIVE.
    
    So no path waives the card.
- **Default `class=write`:** correct.
- **Grant leaks already closed by static `names()`:**
  - The praw `*` expands `registered()` only (tools/policy.ts `effective`).
  - `tool_request` refuses names that are not registered (grow/tool-requests.ts "if (!this.d.grant.registered().includes(tool))"), and this runs before the project grant port.
  - `skillToolAllowed` also requires a registered name.
  
  All three stay closed as long as `names()` stays static (spec §5.8).
- **No AI path to `mcp.enabled`.** HANDLER_KEYS are not in ADMIN_CONFIG_KEYS, so `config_propose` cannot write them (admin/keys.ts `ADMIN_CONFIG_KEYS`). The admin_op `bot_tools` goes through `planBotTools`, which §5.8 makes refuse `mcp_`.
- **Counter keys.** Task ids come from `randomUUID` (db/repos/tasks.ts), so the `tree` CHECK matches. It is the same shape as 040 `ws_run_counts`.
- **Taint propagation** reuses registry "G2-04: the task keeps the taint". The LEARN-1 Gate 1 channel table (docs/security/2026-11-12-gate1-learn-loop.md, "Invariant: no text written by a model in a tainted run…") already covers the stores a tainted turn writes. MCP adds no new store, provided MC-C18 holds.
- **Docker Desktop engine-API reach (WS Gate 1, CVE-2025-9074 note).** `--network none` removes it for MCP containers.
- **D6 (no SDK): agreed.** The SDK's dependency closure is large and its stdio buffer is uncapped. A 64-message line client is small enough to review and fuzz (MC-C11). The SDK fallback is not required.
- **D7:** refusing unknown versions fails closed. Acceptable until the BE3 probe (MC-C11 f).

## Conditions

### Before BE1 (spec amendments)

- **MC-C1 (F-1).** §5.8 also drops `mcp_` from:
  - `withProject` (the `projTools` from `autopilot.toolsFor` and `treeToolsFor`);
  - `approvedToolContext` `projectTools`;
  - `autopilot.toolsForTask`.
  
  The repos' project-tool and tree-tool inserts refuse `mcp_`. Test: insert a `project_tools` row and a `tree_tools` row with `mcp_w_ab_x` directly by SQL, with the host holding that tool active. Then `toolsFor`, `specsFor` and `exec` give "not allowed" in the project, company and replay contexts. A pin asserts that `ToolRequestDeps.grant.registered` and the policy's `registered` never return an `mcp_` name.
- **MC-C2 (F-2).** At add, approve and boot, `docker image inspect --format '{{json .Config.Volumes}}'` must print `null` or `{}`, else E_IMAGE (boot: not loaded). MCP removal runs `rm -f -v <name>`. §3.5 adds `--no-healthcheck`. BE3 asserts that `docker volume ls -q --filter dangling=true` does not grow after a call.
- **MC-C3.** The §3.5 golden argv adds `--hostname mcp`, `--cgroupns=private` and `--ulimit nofile=256:256`. `--security-opt` appears only as `no-new-privileges`. Boot refuses MCP (`off:seccomp`) unless `docker info --format '{{json .SecurityOptions}}'` contains `name=seccomp` and not `unconfined`. After the first `tools/list` write, stdin is closed in `finally`.
- **MC-C4 (F-3, F-8).** §5.7 becomes:
  1. Head-cut the joined text to `8000 + longestSecret - 1` characters (and at most 64 KiB of bytes).
  2. Strip ANSI and C0, strip hidden characters (MC-C5), redact.
  3. Cut to 8000.
  
  Rules for content items:
  - a non-text item maps `type` through the fixed set `image|audio|resource|resource_link`, else `other`;
  - a non-string `text` gives E_PROTOCOL;
  - there are at most 64 content items.
- **MC-C5 (F-4).** Every MCP screen (descriptions, schema text, enums, input screen) refuses on both `INVISIBLE` and the `HIDDEN` class from discord/embeds/approval.ts. Stripping (output) uses a global copy. Tests:
  - a string with two hidden characters;
  - U+E0041 (tag) and U+FE0F in a description, an enum, an input and a result.
- **MC-C6 (F-5).** At add (E_SCHEMA):
  - the rendered text per tool (template description plus `JSON.stringify(z.toJSONSchema(…))`) is at most 2000 characters;
  - per server, at most 16000;
  - per property, the enum values total at most 512 characters.
- **MC-C7 (F-6).** `/mcp show` and the add reply render exactly the model-visible text: the §5.5 description and the `specsFor` JSON. Rendering rules:
  - escape with `escapeCardText` rules;
  - defang URLs (`://` → `:/​/`);
  - `allowedMentions` NO_PING, ephemeral, `suppressEmbeds`;
  - over the embed limit, page it (`page` option) with `hash12` on every page, never cut silently.
  
  Test: a description with `@everyone`, `<@&1>`, `[x](https://e.x)` and a fence triple-backtick renders inert.
- **MC-C8 (F-7, F-9).** The token is `config12 = sha256(canonicalJson({image_id, command, env, tool_class, depts sorted, snapshot_sha256})).slice(0,12)`. It is displayed and required by `/mcp approve` (`^[0-9a-f]{12}$`).
  
  Leaving `active` (quarantine, disable, re-add) expires, in the same transaction, every open `tool` approval whose name starts `mcp_<c>_<slug>_`. The spec names this mechanism; `pre.pin` cannot carry it under strictObject.
  
  Compare-and-set updates:
  - quarantine: `WHERE id=$1 AND status='active' AND snapshot_sha256=$2`;
  - approve: `WHERE id=$1 AND status='pending' AND snapshot_sha256=$2` (row read `FOR UPDATE` inside the lock);
  - re-add clears the approved, quarantine and disabled columns;
  - re-add over `pending` or `active` gives E_EXISTS.
  
  The host entry captured at precheck (hash, snapshot, original names) is the object `run` uses.
- **MC-C9 (F-11).** §6(e) and residual 2 and 3 are reworded as in "Residual risks" below. A rule is added: any migration that widens `mcp_servers_egress_check` or adds secrets re-gates read class (no card) under its own Gate 1. Default `class=write` stays.

- **MC-C11 (rpc).**
  - (a) The byte caps are enforced on Buffer chunks before newline split and before `JSON.parse`.
  - (b) A JSON array (batch) gives E_PROTOCOL for every version, 2025-03-26 included.
  - (c) Client ids are safe integers held in a `Map`. A response must match exactly one outstanding id, else E_PROTOCOL; a duplicate also gives E_PROTOCOL.

## Residual risks (plain words)

1. Docker or kernel flaws could let a malicious image escape. The app can drive Docker (OD-1).
2. Tool descriptions and parameter hints sit in the prompt of every granted run before any call, and those runs are not tainted. A Bot Admin reviews this text in full, and it is frozen by the hash (MC-C6, MC-C7), but a clever wording can still nudge a bot.
3. Read-class tools run with no card. With no network, mounts or secrets, they cannot send data out or change anything outside the container. Their answers can still steer a run. Inside project and company autopilot trees, a steered run's ordinary writes still auto-run, as with web pages today.
4. Answers can be false. The pinned image can act differently per input without changing its tool list.
5. One stuck container (E_STUCK) stops all MCP calls until restart.
6. Each call costs 1–3 s and up to 512 MB, two at a time. Anyone with DB access can edit `mcp_servers` (the same as R5).
7. The protocol version list is assumed until the BE3 probe.
