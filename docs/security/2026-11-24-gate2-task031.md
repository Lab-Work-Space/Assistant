## Findings

**G2T031-01 [Low] Fixed in this audit. `recover()` re-spawned every pending review on each intake `on_ready`.** py-cord fires `on_ready` again after a reconnect with a new session, and `_intake_ready` calls `asyncio.ensure_future(self.ctx.approvals.recover())` each time. Each reconnect therefore started a second head LLM run for every pending dept card, which breaks R11's "one review run per approval" and costs budget. The SQL guard prevents a double decision. Fix: `PgApprovalService.recover` sets a `_recovered` flag before its fetch and returns early when the flag is set. If the fetch raises, the flag is reset, so a later ready can retry. Probe: a failed call, then two overlapping calls, then a third call gives 1 spawn in total. Full suite after the fix: `737 passed, 676 warnings in 42.35s`. Wiring checked in `core/approvals/ext.py`: the service gets `settings=ctx.settings` (the instance the Discord layer injects `is_disabled`/`channel_ok` into), the real classifier, the engine and `sinks_fn`. Tester: add a test where two `recover()` calls produce one review.

**G2T031-02 [Low] Self-approval laundering beyond one hop.** The T031-02 check covers a task the head created directly. Two paths remain: (a) the head creates task A for subordinate X, X creates task B for Y, and Y's request names X as `task_creator`; (b) the head starts a brainstorm (`brainstorm_threads.task_id` NULL) and asks a participant to file the request. In both cases the head can then decide a request it caused. Impact is bounded: the item must be a generic dept item under the threshold (no permission granted), the cap, the human override and the kill switch still apply, and the review prompt says "never decide a request you could benefit from". Remediation (backend): in `_linked_task`, walk the task creator chain (via the parent task thread) and also check the brainstorm owner and participants. Route `requester_is_head` when the head appears anywhere, and re-check in `_head_checks`.

**G2T031-03 [Info] The classifier sees less than the head.** `make_classifier` cuts each field to `[:1000]`, while `summary` can be 4000 characters and the head sees all of it. A request can put a benign first 1000 characters ahead of major content. The head review still applies, so this is not a bypass of a hard control. Remediation: pass `summary[:4000]` (still 8 output tokens), or pass the first and last 500 characters.

**G2T031-04 [Info] `_lookup` does not catch errors from `is_approver`.** If `fetch_member` raises, the command errors out (fail closed, logged as `command.failed`), but the user gets no ephemeral reply. Optional: wrap it in `try/except Exception: ok=False`, as `decide()` does.

## Other domains checked

- Prompt security: review text goes through engine `wrap_untrusted(req.text, "approval")`, and the classifier input is wrapped. The review run has `human_user_id=None`, a null sink and `tools_override`. Only exact `routine` routes to dept. PASS.
- AuthZ: `decide()` keeps the surface check, a fresh `is_approver` (fail closed) and `origin`. The override SQL accepts only `agent:*` decisions before expiry. The DB CHECK forbids `agent:*` on hq, non-generic or access rows. The task Cancel button now uses a fresh `is_approver`. `/setting` requires the exact channel, a fresh approver and a known key. PASS.
- Injection: `task edit` builds `SELECT {field}` only after the field passes the `edit()` whitelist (unknown field raises). Codes are regex-checked before the query. Settings values are validated per key. PASS.
- T031-04 beyond the tested events: `task.incomplete` logs `agent` and `kind=<missing field names>|invalid`, and `approval.channel_fallback` logs `reason=unresolved|not_allowed`, both fixed tokens.
- Output and log privacy: embeds go through `build_embed` with `AllowedMentions.none()`. Replies use `mask_secrets` and are clamped to 2000. Exceptions log only `type(e).__name__`. PASS.
- Deviations accepted: `channel_fallback` is logged only when the id is unresolved or not allowlisted (a dept set to `hq` is a deliberate choice). `recover` runs after the surface is ready. The cancel reason (≤200) goes to `audit_log` only. AI-decided cards keep their buttons for the OQ-6 override.
- Live-only (deploy): run 0002 on a copy of the production DB with the service stopped, and check `integrity_check`/`foreign_key_check`.
