# Security Gate 2: spend trends and department budget control

Verdict: **APPROVED**, with two Low and three Info findings that do not block release.

- The trust boundary holds. No path a model can reach writes a spend.* key or decides an override.
- The lock order cannot deadlock, and the code holds no second pooled connection while it holds row locks.
- The rollup fails closed. Sanitising, posting, the dashboard and the migration meet S1 to S20.

One isolated fix was made during this audit (G2SP-01), with a regression test. The one Low finding against S15 (G2SP-02) is a remediation for backend and is not a release blocker.

## Holes audited beyond S1-S20

- **spendovr id forging or replay.**
  - The id is a 128-bit random value bound to the stored message id and the config channel. A guessed id on another message fails.
  - A replayed click after the decision fails the conditional UPDATE.
  - Once set, the message id is never changed.
  - A click that arrives before `message_id` is stored gets "Unknown action." This is benign.
- **Deadlock and pool starvation.**
  - In `close()`, each transaction does one spend_days upsert, as its last statement, while it holds budget_days rows. Every holder of a shared spend_days row also shares the dept row, or the task row, or (for local calls) the same row set. No transaction waits for budget_days while holding spend_days, so no cycle can form.
  - onStop does a plain SELECT on the dept row (no lock).
  - The pool risk on a burst of onStop calls is noted as G2SP-03.
- **Prototype keys.** `cleanDept` accepts `constructor` and `__proto__`. `effectiveDeptCap` returns a cap only for a `typeof number` value, otherwise Infinity. Caps can be set only for DEPT_IDS, so these keys can never get a cap.
- **Claim scope length.** The longest scope_id is `marketing:99999999:f` (20 characters, under the limit of 32). onStop runs only for a dept with a finite config cap, and those are limited to DEPT_IDS (≤ 9 characters).
- **Stale-month card.** Before this audit, a refusal from the month that had just ended, handled after local midnight, made a card for that month that stayed live for up to expiryHours. Approving it had no effect. This is fixed as G2SP-01.
