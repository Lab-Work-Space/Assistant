# Gate 1 — TASK-031 approvals routing, work codes, channel settings

Scope: design `docs/specs/2026-11-24-approvals-routing-design.md` (D1–D5) and the sa handoff brief R1–R13 (session scratchpad `task-031-sa-brief.md`, main-thread OQ-1..9 resolutions). The destination spec `docs/specs/2026-11-24-approvals-routing-spec.md` does not exist yet, so every condition below is a **spec edit plus a test** that sa/backend must carry into it. Code read as context: approvals service/ext, agent_tools approval/registry, engine, discord approver/buttons/client/syslog/embeds, budget guard, migration runner and 0001.

Verdict: **CONDITIONAL_APPROVE**. Main controls hold up. The decision tools are gated server-side on `trigger == "approval_review"` plus a server-set `approval_id`. The SQL guard plus the DB CHECK limit `agent:*` deciders to dept/generic/no-access rows. Decisions are a structured tool call, never prose. Every human action re-fetches `is_approver`. Migration 0002 is safe. The conditions close three gaps: a false reachability claim, a self-approval laundering path and a budget-accounting break.

## Findings and conditions (owner: backend; sa carries them into the spec)

**T031-01 [Medium] Decision tools are advertised to Praw in every run.** `core/agent_tools/registry.py` `_allows` returns true for `entry == "*"`, and `prompts/assistant/Praw.md` has `tools: ["*"]`. As a result `for_agent(praw)` would list `approval_decide`/`approval_escalate` in chat and task runs. R11's "in no persona's tools" is false. The `not_allowed_here` check still stops the call, and Praw is HQ_ONLY, but an injectable model should not be offered a decision tool. Required: mark both tools override-only (for example `ToolSpec.override_only=True`, or a registry set) so that `for_agent` returns them only when they are named exactly in `override`, never through `*` or `x_*`. Test: `for_agent(praw)` and `for_agent(any persona)` exclude both tools, and `for_agent(head, ("approval_decide","approval_escalate"))` includes them.

**T031-02 [Medium] Self-approval through a subordinate.** Path: a head (for example mali) runs `task_create`, assigning a subordinate. The subordinate's `task_assigned` run calls `approval_request`, so `requested_by` is the subordinate. The head reviews and approves the request. `requested_by != ?3` in `decide_as_head` passes, so the requester ≠ decider rule does not catch this. Required: in the `approval_request` handler, when `ctx.thread_record_id` names a task with `created_by_kind='agent' AND created_by_id = <current head of the routed dept>`, route rule 7 `requester_is_head` → HQ. Also re-check this in the `decide_as_head` pre-checks by storing the originating task id in `payload` (or a column). Test: a head-created task, then a subordinate request, must land at HQ.

**T031-03 [Low, breaks routing] Classifier billing purpose is rejected by the DB.** `usage_events.purpose` CHECK in 0001 allows only `chat,tier2,brainstorm,summary,image,tts,stt,note`. `budget.record(..., "approval_classify")` therefore fails the insert, `guard.record` logs `budget.record_failed` ERROR on every request, and the cost only goes into the in-memory `_unrecorded`. Required: record with purpose `tier2` (same model and pattern as `reply_gate.tier2`) and ref `approval:<id>`. Do not add a value to the CHECK, because that would need a usage_events rebuild.

**T031-04 [Medium] Syslog forwarding (§12.14 interaction).** `code`, `agent`, `status`, `by`, `reason`, `id`, `kind`, `level` and `task` are already in `syslog.FORWARD_KEYS`, so R10's open question closes with **no §12.14 amendment**: use `code`. Because `reason` and `id` are forwarded to #bot-log, the spec must also lock these rules:
- (a) every WARNING `reason` is a fixed token (a `route_reason` enum value, a guard-check name or a denial code). The AI's escalate/decide `reason` text never goes into a log field.
- (b) `settings.denied` and `command.denied` log `id`/`kind` only when the value is a known key or command name; otherwise they log `unknown`. Raw typed keys and codes must not be logged.
- (c) `approval.classify_failed error=` carries only `type(e).__name__` or a fixed code.
Test: forward a log line built from each new WARNING event and assert that no free text appears.

**T031-05 [Low] The per-head daily cap can be refilled by overrides.** The cap subquery counts `approvals.decided_by = 'agent:'||?3`. A human override rewrites `decided_by`, so each override gives the head one decision back. Required: count `audit_log` rows `scope='approval' AND action='ai_decide' AND actor='agent:'||?3 AND at > now-1day` in the same UPDATE guard. Add an index on `audit_log(actor, action, at)`, or reuse `audit_ref_idx` if the query plan is acceptable.

**T031-06 [Low] Reserved actor id.** R3 reserves `agent:system`, but `core/agents/persona.py` accepts any `_ID` value. Required: the loader refuses persona id `system` (and `dept: system`). Test.

**T031-07 [Low] Settings validators.** `approval.channel.<code>` must also refuse `SETTINGS_CHANNEL_ID` and the System log channel id, not only `ADMIN_NOTIFY_CHANNEL_ID`. Import boundary (rule 29): `core/settings/service.py` must not import `core.discord`. Inject the channel resolver and `gate.channel_ok` from `core/discord/commands.py` (the Discord layer) and keep the presenter's own `channel_ok` re-check at post time (R7). `/setting` keys are checked against the fixed key list before any DB access.

**T031-08 [Low] Slash command input and lookup order.** Bound `code` input to 24 chars and `value` to 256 chars in the command definition. Do not add autocomplete that lists codes. Resolve requester-match from the DB before calling `is_approver`, so that a non-requester triggers at most one `fetch_member` per command. Classifier and routing run **before** `pool.transaction()`: no LLM call may happen while holding BEGIN IMMEDIATE. The code is allocated inside the transaction, as R2 says. The new command module must not add listeners (`tests/test_discord_layer.py::test_only_one_add_listener_call_site` asserts exactly 2).

**T031-09 [Low] Migration 0002 probes.** Static review passes (see below). Required in A1: run on a copy of a populated legacy DB, then `PRAGMA integrity_check` = ok and `PRAGMA foreign_key_check` empty; migrate only with the service stopped (deploy step). The local SQLite version is 3.53.4 and the VPS has 3.46.1, so window functions and ADD COLUMN CHECK both work. Note: after a restart, pending dept rows have no reviewer (`_review` tasks are in-memory). The spec must either re-spawn reviews for `status='pending' AND level='dept'` at start, or escalate them with `head_no_decision`.

## Areas reviewed with no condition
- **Chat injection / tool reachability**: `approval_review` is set only by `PgApprovalService._review`. No tool or model path builds an `AgentRequest` with that trigger, and every current `AgentRequest(` site was checked. The tools take no id argument. The review run uses `human_user_id=None`, a null sink and `tools_override` (a replacement, not a union, per `registry.for_agent`). PASS after T031-01.
- **Card-text injection into the head**: the worst case is a wrongly approved **generic** item under the threshold. Generic grants no permission (`approval_request` docstring "informational, grants no permission"). The generic handler only wakes the requester with its normal tools. There are four bounds: the SQL guard, the DB CHECK, the human override until expiry, and the kill switch. Accepted.
- **Value understatement (residual, accepted)**: `value_thb` is set by the requesting AI. The owner rejected "approval triggers never depend on LLM numbers" (security rules, Rejected list), so this is not a condition. Recommended, not required: route HQ when title/summary/reason contain an amount (digits with บาท/THB/฿/k/แสน/ล้าน) ≥ threshold, and cap the daily total AI-approved value per requester.
- **HQ authority**: `decide()` keeps the fresh `is_approver` check. `decide_as_head` refuses HQ_ONLY personas, level `hq` and a non-head persona. The DB CHECK forbids `agent:*` on hq/non-generic/access rows. The override SQL only flips `agent:*` decisions, before expiry, and exactly one concurrent override wins. Cancel is soft and pending-only. PASS.
- **Settings authz**: `cmd_gate` plus an exact `channel_id == SETTINGS_CHANNEL_ID` (no threads) plus a fresh `is_approver`, with audit and log in one transaction. PASS with T031-07.
- **Code enumeration**: codes are sequential but already public on cards. A single ephemeral "not found or not allowed" reply covers enumeration, and approver status is checked fresh. The residual timing difference is Info.
- **Migration 0002 safety**: no FK, trigger or view references `approvals` (only `tasks` is referenced, and it gets ADD COLUMN only). The runner wraps the file in one `BEGIN IMMEDIATE` with ROLLBACK and takes a pre-migrate backup. Every legacy CHECK is a subset of the new ones (same `decided_by` forms, same status/decided pairing). Backfilled rows get `value_thb NULL`, so they can never be AI-decided. The counter seed equals the row count. PASS.
- **Output**: `approval_embed` goes through `build_embed`, which masks and clamps every field (title 256). Sends use `AllowedMentions.none()`. PASS.
