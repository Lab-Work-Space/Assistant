# Security Gate 1 — TASK-040 Phase 2A (MCP behind a policy gateway)

## Verdict

**CONDITIONAL_APPROVE.** The gateway's structure is sound:
- default-deny classes, pinned with tool_sha256;
- refusals that never reach the server;
- irreversible actions behind HQ cards. The DB CHECK forbids agent decisions on non-generic kinds, and the router sends every non-generic kind to HQ (`Router.route`: `if kind != "generic": return hq("kind_dangerous")`);
- an at-most-once conditional-UPDATE claim;
- override-only ToolSpecs, so Praw's `"*"` never picks up MCP tools (`Registry.for_agent`).

There are 14 conditions:
- **Must be folded before MCP-02 and MCP-04 start:** the three Highs (G040-01, 02, 03) and G040-04, 05.
- **Gate 2 verifies:** all 14.

## Conditions

**G040-01 [High] Id and path injection through scoped or id arguments (scope escape, catch-all bypass).**

Evidence:
- §3.10 matches `owner/repo` with `fnmatch`. Python's `*` matches `/`: `fnmatch('org/dev-x/../../org/mkt','org/dev-*')` returns `True` (run during this review).
- Praw is unscoped. Hostinger `params` is free-form inside `execute`, and ClickUp ids flow straight into the bot's resolver URLs.
- If any server or HTTP client leaves path segments unescaped or resolves `..`, then:
  - a head can write outside its department;
  - Praw can reach endpoints that the operation id does not name, such as billing behind a `write` operation.
- This review did not read the servers' URL builders. The control below must not depend on them.

Required, §3.3 R1: insert a new step 4a. It runs on the final effective args (after force, per G040-11), before classify, and applies to every persona:
- "Every argument named by a policy `scope.arg`, every dispatch `arg`, and every key listed in the policy's new `ids = {<dot path> = <kind>}` table must match its kind regex:
  - `gh_owner`/`gh_repo` `^[A-Za-z0-9_.-]{1,100}$`, and not `.`, not `..`, and not containing `..`;
  - `clickup_id` `^[A-Za-z0-9_-]{1,64}$`;
  - `google_file_id` `^[A-Za-z0-9_-]{10,200}$`;
  - `google_calendar_id` `^[A-Za-z0-9._%+-]{1,200}@[A-Za-z0-9.-]{1,200}$` or `primary`;
  - `hostinger_id` an integer, or `^[0-9]{1,12}$`.
- On a failure, refuse `invalid_id`.
- Hostinger: any string value anywhere in `params` that contains `/`, `\`, `?`, `#`, `%` or `..` → `class_blocked`. This holds unless the operation's policy lists that key in `free_text`."

Required, §3.10:
- "Scope matching compares `owner` and `repo` separately: `owner == scope_owner` and `fnmatch(repo, glob)` with globs that contain no `/`."
- "The ClickUp resolver and the Drive ancestry walk apply the same regex and URL-quote each segment (`urllib.parse.quote(v, safe='')`)."

Required, §7 probes: add P-HPATH, P-GHPATH and P-CUPATH. Each records whether that server encodes path parameters. The results are informational only; the control above stays in place either way.

Required, §5.3: add `invalid_id` to the refusals.

AT-8, add these cases:
- `repo="dev-x/../../mkt"` → `invalid_id` for a head and for Praw;
- Hostinger `params.virtualMachineId="1/../../billing"` → refused for Praw;
- ClickUp `task_id="a/../b"` → `invalid_id`, and the resolver is not called.

**G040-02 [High] Hostinger write and irreversible operations that equal host control (a settings bypass).**

Evidence:
- Appendix A classes `vps_docker_create` and `vps_docker_update` as `write`. A compose project can mount `/`, use host networking or run privileged. That equals editing the firewall, SSH keys or the root password, all of which are `settings` (D2).
- `vps_virtual-machines_recreate` can carry a password, a post-install script or a public key. That is `set-root-password`, `post-install-scripts_*` and `public-keys_*` by another route, and a password would show in clear on the HQ card.
- D9 means one injected issue body can drive these calls.

Required, Appendix A Hostinger:
- Move `vps_docker_create` and `vps_docker_update` to `settings`. The owner may lower them to `irreversible`, so the card shows the whole compose file, as a recorded decision.
- `vps_virtual-machines_recreate`: add rule `present params.password | params.panel_password | params.post_install_script_id | params.public_key → settings`. Do the same for `vps_backups_restore` and `vps_snapshots_restore` if they accept these keys (check against the `dump`).

AT-5: one case per rule, each giving `class_settings`, with zero server calls.

**G040-03 [High] Workflow-file pushes, public visibility and the OQ-1 blast radius.**

Evidence:
- `create_or_update_file`/`push_files` (`write`) can write `.github/workflows/*`. That leads to Actions runs that use repo secrets and paid minutes, which is `payment`/`settings` by the backdoor.
- `create_repository`, `create_gist` and `fork_repository` take no visibility or owner rule. Making something public is "sharing" under design §7.
- With Administration:write (OQ-1), a stolen token can delete, transfer or change the visibility of every repo (residual from the same uid, §2).
- `--lockdown-mode` is still `assumed`.

Required, §3.1 least-privilege GitHub row, replace with:
- "Fine-grained PAT, resource owner = the company org only, expiry ≤ 90 days.
- Permissions: Contents/Issues/Pull requests RW, Metadata R, Actions R, Administration RW (OQ-1).
- Not granted: Workflows, Secrets, Webhooks, Members or org administration.
- The central account is an org member, never an org owner."

Required, Appendix A GitHub:
- `create_or_update_file`, `push_files` and `delete_file`: rule `path` (for `push_files`: any `files[*].path`) glob-matching `.github/workflows/**`, `.github/actions/**`, `.github/CODEOWNERS`, `CODEOWNERS` or `.github/dependabot.yml` → `settings`.
- `create_repository`: force `private = true`.
- `create_gist`: force `public = false`.
- `fork_repository`: force `organization = github_default_owner`. If the schema lacks the field, the tool is `blocked`.

Required, §3.2 pre-conditions: "GitHub starts only if `--lockdown-mode` is accepted (P-GHFLAGS). Otherwise the state is `not_configured`."

AT-5:
- a workflow path in `push_files` → `class_settings`;
- `create_repository` arrives at the fake server with `private=true`.

**G040-04 [Medium] Env-source and literal-env allowlist.**

Evidence: §3.14 `[env] X = { from = "...", secret = true }` lets any server.toml name any bot variable, for example `DISCORD_BOT_TOKEN_*` or `ANTHROPIC_API_KEY`. Nothing restricts literal env keys either:
- `NODE_OPTIONS` defeats `--permission`;
- `API_BASE_URL` and `API_HEADERS` are "never pass", but nothing enforces that.

Required, §3.14: "`from` must match `^MCP_<SVC>_[A-Z0-9_]+$`, where `<SVC>` is the server.toml `name` uppercased. Literal env keys must be in a per-service allowlist constant in `core/mcp/host.py`:
- github: `GITHUB_TOOLSETS`;
- clickup: `CLICKUP_MCP_MODE`;
- google: `WORKSPACE_MCP_CREDENTIALS_DIR`, `WORKSPACE_ATTACHMENT_DIR`, `WORKSPACE_MCP_DISABLE_LOCAL_FILES`, `ALLOWED_FILE_DIRS`;
- hostinger: none.

Any key matching `^(NODE_|PYTHON|LD_|DYLD_)` or `API_BASE_URL|API_HEADERS|OAUTH_ISSUER|DEBUG` is refused. This applies both to literal keys and to the destination key of `from` mappings. Anything else → PolicyError at load."

AT-10:
- a server.toml with `from = "DISCORD_BOT_TOKEN"` → PolicyError;
- `NODE_OPTIONS` literal → PolicyError.

**G040-05 [Medium] R-CTX is not specified, and the engine cannot do it as written.**

Evidence:
- `engine.py` builds `allowed` once (`allowed = self.ctx.tools.for_agent(persona, req.tools_override)`), and `invoke` receives that list.
- `ToolContext` (`core/interfaces.py`) has no mutable slot, so an `mcp_use` handler cannot add tools.
- R-CTX exists only in "Owner answers", and MCP-04 lists "engine.py (offer line only)".

Required, a new section §3.4a R-CTX:
1. "`mcp_use(service)` is one static registered ToolSpec with `override_only=True`. Its schema is `{service: enum["github","clickup","google","hostinger"]}`, additionalProperties false. The registry allows one spec per name, and `_invoke` requires the registered object. The handler refuses a service this persona is not allowed with `not_allowed`, and that refusal is audited.
2. engine.py, in the same `if req.tools_override is None and self.ctx.mcp:` branch:
   - `allowed += await self.ctx.mcp.initial(persona, req.text)`. This returns `mcp_use` (only if `offer(persona)` is non-empty) plus the tools of services named in `req.text`, taken from `offer(persona)`.
   - `ToolContext` gains `offered: list | None` (server-set), pointing at the same `allowed` list.
3. The `mcp_use` handler recomputes `gateway.offer(persona)` at call time and appends only those specs for that service that are not already in `ctx.offered`, by identity, never by name lookup in the registry. A refused service returns `mcp_refused:not_allowed` and is audited.
4. `mcp_use` never runs when `ctx.offered is None` (runs with an override, such as approval_review).
5. `gateway.handle` re-runs R1 steps 1–4 on every call. R-CTX never bypasses them."

- MCP-04 files: change to "engine.py (R-CTX lines) and core/interfaces.py (ToolContext.offered)".
- Add AT-18, covering:
  - a head calling `mcp_use("hostinger")` without access → refused, audited, and nothing added;
  - a duplicate `mcp_use` adds no duplicate tool;
  - an approval_review run offers neither `mcp_use` nor MCP tools;
  - `/move` mid-run → the next MCP call is refused at step 3;
  - a team member gets no `mcp_use`;
  - `mcp.enabled=off` → no `mcp_use`.

**G040-06 [Medium] Google: spoofable ancestry, unparented creates, local files and listeners.**

Evidence:
- §3.10 parses `parents` from `get_drive_file_permissions` text output. That output also carries the file name, which any sharer controls, so a file named `...parents: <in-scope id>` can spoof scope.
- Creates without `folder_id` are not defined.
- Stripping `file_path`/`file_url`/`fileUrl` is a denylist. Arguments such as `insert_doc_image`'s image source, or import sources, may accept local paths (P-GLOCAL is `assumed`).
- `get_drive_file_download_url` writes files to local disk with no bound.

Required, §3.10 Google:
- "Ancestry comes only from `structuredContent`, if P-GPARENTS shows the server returns it, with every id passing `google_file_id` and every chain reaching a `google_folders` id within depth 10. If the server returns only text, a head's write to an existing Drive, Docs or Sheets id → `scope_unverified`, and no text parsing happens (global rule 25: a hand-written parser of untrusted text, here a file name, may only be a second layer). Creates into a listed folder stay allowed."
- "Create or copy tools with no folder or parent argument → `scope_unverified` for heads."

Required, policy load (§3.14): "For a Google tool, any inputSchema property whose name matches `(?i)(path|file|url|uri|source|dir|attachment)` must appear in that tool's `strip` or `allow_args`. Otherwise the tool is blocked with `mcp.tool_invalid`."

Required, Appendix A: `get_drive_file_download_url` → `blocked`.

Required, §7: add probe P-GPORT. It asserts that the stdio Google server listens on no TCP port at runtime, including during a token-refresh failure. If it does listen, the listener must bind to 127.0.0.1 only, and this becomes a Gate-visible change.

AT-8: a spoofed-name fixture → `scope_unverified`. AT-5: an unreviewed `image_source`-style property → blocked.

**G040-07 [Medium] The approval card must show exactly what runs, and replay must honour the kill switches.**

Evidence:
- `approval_embed` passes the summary through `_m` (`mask_secrets(...)[:4000]`). So the args a human sees can differ from the args the hash binds.
- Pretty-printing 3000 canonical chars can exceed `summary ≤ 4000` (the 0005 CHECK).
- The model controls the values, so a value can imitate the `Tool:` lines.
- Replay (§3.6 step 2) does not re-check `mcp.enabled`.
- R1 step 3 lets Praw through without `is_disabled`.

Required, §3.6 Request:
- "Refuse `args_unreviewable` if `mask_secrets(canonical_args) != canonical_args`.
- Render the args in one fenced code block, with every backtick replaced by `ˋ`.
- Refuse `args_too_large_for_approval` when the rendered summary is over 3900 chars."

Required, §3.6 step 2, add these checks:
- "`mcp.enabled` is on";
- "`payload.mcp.persona == row.requested_by`";
- "`not settings.is_disabled(persona)`".

Required, R1 step 3, Praw clause: "`persona.id == "praw" and not settings.is_disabled("praw")`."

Required, §5.3: add refusal `args_unreviewable` and replay states `refused_at_replay:mcp_disabled|persona|disabled`.

AT-6:
- args containing a token-shaped string → `args_unreviewable`;
- `mcp.enabled=off` between approve and replay → `refused_at_replay:mcp_disabled`.

**G040-08 [Medium] Elicitation scope and other client callbacks.**

Evidence: §3.15 accepts any elicitation that arrives while the replay lock is held. Other calls on the same session run concurrently (semaphore 4). The callback cannot tell which call asked, so a concurrent call whose prompt contains the same `owner/repo` would be auto-confirmed.

Required, §3.15:
- "A replay of a tool listed `elicits = true` in the policy acquires all `max_concurrency` permits of that server (exclusive).
- The callback accepts only if the requested schema has exactly one property, it is a required string, and the request text contains the approved `owner/repo`.
- The ClientSession is built with no `sampling_callback` and no `list_roots_callback`. Server `logging` notifications are discarded, never logged."

AT-15: a concurrent non-replay call during a replay waits; a sampling request from the fake server is refused.

**G040-09 [Medium] OQ-2 credential storage, and the Node permission scope.**

Evidence:
- §3.7 grants `--allow-fs-read=<pkg dir>,<data dir>`. If "data dir" means `<data_dir>`, the Node servers can read the SQLite DB and Google's refresh token.
- No permission check is specified for `<data_dir>/mcp/google/credentials`.

Required, §3.7:
- "Node `--allow-fs-read`/`--allow-fs-write` name only `mcp/<svc>` (package) and `<data_dir>/mcp/<svc>`."
- "Before starting Google, the host checks two things:
  - `<data_dir>/mcp/google/credentials` is a directory (not a symlink, via lstat), owned by the euid, mode 0700;
  - every file in it is owned by the euid and has mode 0600.
  Otherwise the state is `not_configured` with ERROR `mcp.creds_perms`. `google-auth` creates the directory with these modes."

Required, §3.2: "The OAuth consent shows only the calendar, drive, documents and spreadsheets scopes (plus openid/email). The dedicated account has 2-step verification and no admin role. Tokens go in `.env.local` (gitignored)." Also add `/.env` to `.gitignore` (today only `/.env.local` and `/.env.*.local` are ignored, while §2 speaks of "the repo `.env`").

AT-10: credentials at mode 0644 → `not_configured`.

P-NODEPERM, run against the real ClickUp and Hostinger servers, also records that the DB path and `<data_dir>/mcp/google` cannot be read under the flags.

**G040-10 [Low] In-process SDK logging bypasses the "no raw args" rule.**

Evidence: `install_logging` pins only `LIBRARY_LOGGERS` (httpx, discord, aiohttp) to WARNING, and sets the root logger to `LOG_LEVEL`. Under DEBUG, the `mcp` SDK's loggers would send raw JSON-RPC (args and results) through `MaskingHandler`, which masks secrets but not args.

Required, §3.8: "Add `"mcp"` to `LIBRARY_LOGGERS` (`core/functions/logs/logsystem.py`)." Add that file to MCP-05.

AT-12: run with `LOG_LEVEL=DEBUG`, capture the emitted log lines (global rule 16), and grep them for a sentinel argument.

**G040-11 [Low] Classify order, and rule-operator semantics.**

Evidence:
- Step 5 classifies "with the effective args", but the effective args only exist after step 8 (force and attribution).
- `equals` and `contains` are case-sensitive, and there is no array operator, which `push_files` needs (`files[*].path`).

Required, R1:
- "Steps 8 (attribution and force) run before step 5. Classify, scope and hash all use the same final effective args."
- §3.14: "String comparisons in rules and dispatch use `strip().casefold()`. A matching `equals` or `in` value is rewritten to its normalised form. Paths may use `[*]`: the rule matches if any element matches. A path whose type differs from the one expected → the rule matches (fail toward severity)."

AT-5: `state="CLOSED"` raises the class; `files[1].path` matches a workflow path.

**G040-12 [Low] OQ-5 audit reconciliation, the daily cap and refusal floods.**

Evidence:
- §3.8 says "one row for every outcome", but OQ-5 says reads go to the log only.
- §3.11 counts the daily cap from audit `action='call'`, so reads become uncapped per day.
- Refusals come before the step-7 rate limit, so a looping model writes unbounded audit rows.

Required, §3.8:
- "Audit rows: every non-read call (with its outcome), every refusal, every approval request, every replay, and every `mcp_use` refusal.
- Successful or erroring `read` calls are logged only.
- The class is the final class after rules."

Required, §3.11:
- "The daily cap counts reads and non-reads in an in-memory counter. It is seeded from the audit count of today's non-read calls; reads start at 0 after a restart (accepted).
- Refusals count against `mcp.calls_per_min`.
- After a persona hits `rate_limited`, further refusals in that minute are logged only, never audited.
- There is a per-run cap of 40 MCP calls."

AT-11 and AT-12 are updated to match.

**G040-13 [Low] Supply chain specifics.**

Required, §6 and MCP-07 `scripts/mcp-install.sh`:
- "`set -euo pipefail`; `curl --proto '=https' --tlsv1.2 -fsSL`; download into a fresh directory under `mcp/<svc>/`.
- The sha256 is compared against the value committed in `server.toml` (the anchor) and also against the release checksums file. `gh attestation verify` is required when gh exists.
- Extract only the named binary member.
- Install pip with `--require-hashes --only-binary=:all: --no-deps`, and npm with `npm ci --ignore-scripts` from a lockfile v3 that has `integrity` for every package.
- The host re-hashes the GitHub binary at each start. On a mismatch the state is `not_configured`."
- The transcribed GitHub hashes went through a fetch summariser (spec footer), so Gate 2 re-verifies them.

AT-16: a mismatch against `server.toml` is refused, even when the downloaded checksums file agrees with the download.

**G040-14 [Low] ClickUp resolver redirect and the token.**

Evidence: §3.10 uses stdlib urllib. That client follows redirects, and it copies headers added with `add_header` (including `Authorization`) to the new host.

Required, §3.10:
- "The resolver uses an opener whose redirect handler raises on any 3xx, and sends the token with `add_unredirected_header`.
- The host is fixed at `https://api.clickup.com`.
- The response is read with a 1 MiB cap."

AT-8: a 302 from the fixture → `scope_unverified`, and no second request.

## Notes (not blocking)
- Masking: `ya29.` already exists. Keep the new regexes idempotent (global rule 14) and add them to the vector test.
- GitHub `enable_toolset` and dynamic toolsets stay unclassified, and therefore blocked. Add that to AT-2.
- macOS isolation: an optional `sandbox-exec` profile for the GitHub and Google servers would deny `~/.ssh`, the repo, and other servers' `<data_dir>/mcp/*`. It is a cheap step before the Phase 2B sandbox. Owner option.
- The approval payload keeps the full args in SQLite (it must, for replay). The DB is in the same-uid residual.

## Areas reviewed with no condition
- Approval decisions: `decide` overrides only `agent:*` decisions, so a human approval of `mcp_irreversible` cannot be flipped. `decide_as_head` SQL requires `kind='generic'`. Rejected cards call the generic wake. PASS.
- Claim and recovery: one conditional UPDATE with a 15 min window. `claimed` → `unknown` at restart. No automatic retry. PASS.
- Offer isolation: `override_only` MCP specs, and `for_agent` exact-match on overrides. The registry checks the identity of the offered spec (`self._tools.get(spec.name) is not spec`). PASS.
- Heads at call time: `/fire` and `/move` clear `approval.head.<code>` (`core/growth/personas.py` `_clear_head`). PASS.
- Output path: the engine applies `wrap_tool_result(name, ok, mask_secrets(raw))`; `_escape` covers nested tags; 32 000 cap; OAuth URLs dropped. PASS.
- Migration 0005: the FK-off runner path is correct for the `lessons.approval_id` reference. `foreign_key_check` runs before COMMIT, and `foreign_keys=ON` is restored in `finally`. PASS.
- Hostinger `execute` takes `{operation, params}`, not code (README). `multi-execute` (step chaining) is blocked. PASS, with G040-01.

## Residual risk (owner acceptance required, add to spec §6)
- D9 with unscoped Praw: text injected into a tool output can make Praw copy private Drive, ClickUp or repo content into an outward write, such as an issue comment, an event invite to an external guest, or a doc. The bounds are the untrusted wrapper, lockdown mode, G040-03, rate limits and the audit. There is no content-flow control.
- Reversible but disruptive writes (VM stop or restart, closing issues, trashing files) run without approval under D3. One injected run can cause an outage, bounded by `writes_per_min`.
- Same uid on the Mac (§2): any compromised server can read every token, including Discord's, and the Google refresh token. With OQ-1, the GitHub token can delete or transfer any org repo the account administers.
