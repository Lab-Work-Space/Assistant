## Deviation rulings

1. **Decide task created `doing`: ACCEPTED, conditional on G2-03.** `runOwner` returns early when "task.status !== 'todo'", so no owner run races the wake. The boot reset is the gap.
2. **Claim row before decide-task creation: ACCEPTED.** A claim whose decide task was never created names a run id that no task has, so rule 7 cannot be met through it. It still counts toward the caps, which is the safe direction.
3. **New code R_ERROR: ACCEPTED.** It has fixed text, and nothing is moved.
4. **Claim outcomes `claim #n …`: ACCEPTED.** They match the Gate 1 table. The counts filter on "LIKE 'claim %'", and resolve retries on `= 'retry'`.
5. **Cancel reason as the task.changed summary: ACCEPTED.** It is `neutralise` → `redactText` → fold → 300. Today no consumer shows it for `cancelled`: the `reportEnded` cancelled branch and `teamtalk.ended` cancelled branch print the title only. Any future consumer must treat it as model text.
6. **`healing.md` for 9 heads; praw gets the tool via "*": ACCEPTED.** Authorisation is all in the port. Praw can act only as the code-derived decider, from its own parent task.
7. **The needs-owner list also shows tasks waiting on an approval: ACCEPTED.** It is fixed text plus escaped titles.
8. **update_task "not found" text no longer echoes input: ACCEPTED.** This is required by HL-C15.
9. **A Bot Admin person lift still needs personLiftsPerDay > 0: ACCEPTED.** 0 means the owner has switched H3a off, and admins can still write in the room.
10. **A lift stays if the post fails after lift(): ACCEPTED.** It is counted against the cap, and nobody can force a post to fail on purpose.

## Taint save points (global rule 9)

These are the places where a tainted heal run can store something that a later run reads:
- **The child's description.** A retry appends the instruction frame there. The child is tainted in the same UPDATE.
- **The parent or decide task.** It takes the blocked task's taint before its run starts.
- **The cancel reason.** It goes into the `task.changed` summary, which no consumer shows today.
- **Claim and audit rows.** These hold code text only: ids, codes and actor keys.

None of these lets a later untainted run read the text unmarked.
