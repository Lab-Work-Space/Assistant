## Verdict

The gateway decision order is as Gate 1 required:
- effective args, then the id check and classify on the same args;
- scope, rate, then approval;
- replay re-checks enabled, persona, disabled, hash, role, tool hash, class and scope;
- R-CTX only ever adds specs from a fresh `offer_service`.

Every `tool_sha256` in `mcp/*/policy.toml` is still `""` (PENDING). So today no MCP tool is active. Every tool is in the `changed` state and is refused at the start of `Gateway.handle`.

These must be closed before any hash is filled or MCP is enabled in production:
- **Blocking:** G2T040-01, 02, 03.
- **Required:** the conditions listed below.

## Findings

**G2T040-01 [Medium] Node `--permission` flag form grants nothing on Node ≥ 20.7, so ClickUp and Hostinger cannot start.**

Evidence:
- `host.prepare` builds `f"--allow-fs-read={cfg.root},{svc}"`.
- Probe on the installed Node v24.15.0: a comma list gives `ERR_ACCESS_DENIED` for files in *either* path. Two separate `--allow-fs-read` flags work.
- `tests/test_mcp_host.py::test_node_permission_scope_and_pin` asserts only the flag string, never the effect.

Impact:
- The failure is closed (the servers cannot load `node_modules`).
- But it invites an operator to set `node_permission = false`, which removes the only filesystem restriction on the Node servers.

Remediation (backend + tester):
- Pass one `--allow-fs-read=` per path.
- Add a behavioural test with real `node` that reads the package (allowed) and the DB path (denied).
- Refuse `node_permission = false` at load for clickup and hostinger.

Not self-fixed, because the test that the tester owns pins the broken form.

**G2T040-02 [Medium] The GitHub binary re-hash compares against the tarball hash, so it always fails.**

Evidence:
- In `host.prepare`, the check `_sha256_file(cmd) != want` uses `want = pin.sha256[<platform>]`.
- Those values are release *tarball* hashes, confirmed against the release checksums file below.
- `mcp-install.sh` writes a `bin/github-mcp-server.sha256` sidecar that nothing reads. It is gitignored next to the binary, so it cannot act as an anchor.

Impact: GitHub is always `not_configured` (`pin_mismatch`).

Remediation:
- Commit a separate `[pin] binary_sha256 = {<platform> = ...}`.
- The install script checks the extracted binary against it after the tarball check.
- The host re-hashes the binary against `binary_sha256`.
- Delete the sidecar.

**G2T040-03 [Medium] The Python lock was not regenerated for `mcp==1.30.0`, and no CVE scan was run.**

Evidence:
- `pyproject.toml` adds `mcp==1.30.0` with a comment that the lock "must be regenerated".
- `constraints/requirements.lock` and `dev.lock` have no diff and no `mcp==` line.
- The transitive deps (`httpx-sse`, `sse-starlette`, `starlette`, `uvicorn`, `pydantic-settings`, `python-multipart`, `pyjwt`) are unhashed.
- `pip-audit`, `osv-scanner` and `trivy` are not installed. `npm audit` needs the network, which this agent may not use.

Remediation (devops):
- Regenerate both locks with `--generate-hashes`.
- Then run `pip-audit -r constraints/requirements.lock`, `pip-audit -r mcp/google/requirements.lock`, and `npm audit --package-lock-only` in `mcp/clickup` and `mcp/hostinger`. Record the advisory DB date (global rule 18).
- Any HIGH or CRITICAL finding = REJECT.

Why this is not a FAIL (compare the Slice A precedent):
- `deploy/install.sh` installs only with `--require-hashes -r constraints/requirements.lock`.
- So production gets no `mcp` package, `core.mcp.ext.init` catches the import error, and MCP stays off (fail closed).
- Nothing unhashed reaches production until the lock is regenerated, and then this scan is required.

**G2T040-04 [Medium, FIXED] Workflow / CODEOWNERS path rules could be bypassed with dot-segments or percent-encoding.**

Evidence: `classify(push_files | create_or_update_file)` returned `write` for these paths:
- `.github/./workflows/a.yml`
- `.github//workflows/a.yml`
- `.github%2Fworkflows%2Fa.yml`
- `CODE%4FWNERS`

The cause: `_hit` `contains` compared only `strip().casefold()`.

Impact:
- The PAT without the Workflows permission still protects `.github/workflows`.
- It does not protect `.github/actions/**` (composite actions run with repo secrets) or CODEOWNERS.

Fix: see "Fixed in this audit" (1).

Remaining work:
- policy: add `.github/dependabot.yaml` (it still classifies `write`);
- tester: add a regression case per bypass shape above.

**G2T040-05 [Low, FIXED] The replay result reached the model raw.**

`replay.replay` put `out[:2000]` into the wake `text` with no `mask_secrets` and no external-data prefix. Normal tool results get both.

Fix: see "Fixed in this audit" (2).

**G2T040-06 [Low, FIXED] The `access.toml` comment contradicted the loader.**

- The comment told the owner to write `"acme/dev-*"`.
- `parse_access` rejects any `/` (`access_bad_glob`).
- So following the comment would disable MCP at load.

Fix: see "Fixed in this audit" (3).

**G2T040-07 [Low] `create_repository` scope-checks one owner but calls with another.**

- When `organization` is absent, `Scope.check` substitutes `github_default_owner`, but the call is sent without `organization`.
- Praw (unscoped) creates the repo in the bot account's personal namespace.
- Remediation: force `organization = "$access:github_default_owner"` (as `fork_repository` does), or treat an absent value as `scope_unverified`.

**G2T040-08 [Low] Method-switched GitHub tools use a denylist.**

- `pull_request_review_write` and `projects_write` raise only on `method contains "delete"`. Any other method stays `write`.
- Remediation: convert both to `dispatch` (an allowlist; unknown → blocked) from the `dump` before their hashes are filled.

**G2T040-09 [Low] SDK root-logger calls bypass the `"mcp"` logger pin (G040-10).**

- `mcp/shared/session.py` calls `logging.warning(f"Failed to validate notification: {e}. Message was: {message.message.root}")` and `logging.warning(f"Failed to validate request: {e}")` on the *root* logger.
- So server-controlled content reaches the log at WARNING (masked, but it is raw protocol data).
- Remediation: a filter on the root `MaskingHandler` that drops or replaces records whose `pathname` is inside the `mcp` package. AT-12 should send a malformed notification.

**G2T040-10 [Low] The approval card can render differently from what runs.**

- `_request` renders `shown` with `ensure_ascii=False`.
- Bidi and other Unicode format characters (category Cf, such as U+202E) and lookalikes pass `args_unreviewable`.
- Remediation: refuse `args_unreviewable` if any character in `canon` is in category Cf or Cc.

**G2T040-11 [Low] The Google child runs with the bot's umask.**

- A refreshed token may be written at 0644.
- The 0700 directory contains it, but the next start fails `check_creds` (`not_configured`).
- Remediation: set `UMask=0077` in the systemd unit, and on the Mac dev path set `os.umask(0o077)` before spawning. Alternatively, re-chmod files in `credentials` at start before checking.

**G2T040-12 [Low] The ClickUp scope checks only `scope.arg`.**

- `Scope.check` (`clickup_space`) resolves only the named arg.
- If `updateTask`, `createTimeEntry` and similar tools accept a second id (`list_id`, `parent`) that moves or targets another space, the write leaves the department.
- Remediation: resolve every present key in `ids` of kind `clickup_id` against the scope. Verify against the `dump`.

**G2T040-13 [Info] Functional fail-closed notes.**

- `_PATHISH` matches `file_id`, and every Google `allow_args = []`. So any Google tool with a `file_id` property will be `tool_invalid` (never offered) until `allow_args` lists it.
- `USER_GOOGLE_EMAIL` is `secret = true`, so `add_exact` masks it. Any future Google `irreversible` tool that forces it would always be `args_unreviewable`.

**G2T040-14 [Low] `python -m core.mcp dump` prints server-supplied tool names raw to the terminal (global rule 16).**

- `dump` prints `{n}` directly.
- A hostile server name can carry terminal escape sequences.
- Remediation: print `host._safe(n)`.

## Residual risk (owner acceptance required)
- **No OS sandbox on the Mac or the host.** The GitHub (Go) and Google (Python) servers run as the bot's uid with an unrestricted filesystem. They can read:
  - `.env.local` (every token, including Discord);
  - the SQLite DB (approval payloads with full args);
  - `~/.ssh`;
  - other services' `<data_dir>/mcp/*`.
- The Node permission model (once G2T040-01 is fixed) limits only the filesystem and child processes, never the network.
- Mitigation option (Gate 1 note): a `sandbox-exec` profile, or a dedicated macOS user per server, before Phase 2B.
- The Gate 1 residuals (D9 with unscoped Praw, disruptive reversible writes, same-uid token theft) are unchanged.
