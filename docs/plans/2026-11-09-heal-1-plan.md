# HEAL-1 plan

Spec section map: 2.1 -> B1-B4, B6; 2.2 -> B7, B8; 2.3 -> B9; 2.4 -> B10; 2.5 -> B11, B12; 3 -> D1, B5; 4 -> every build task (error handling AC); 5 -> unit tests inside each build task, integration + acceptance in T1/T2.

Conventions for all build tasks: TypeScript, unit tests in vitest (`npm test`), DB tests via `npm run test:int` (test Postgres 127.0.0.1:54329, docker-compose.test.yml). Each task ships its own unit tests from spec section 5. Every timer/step is wrapped in `safe(...)`, logs the error name only, and is a no-op while halted, on an off day, or when `heal.enabled` is off (except H4, H5). Security Gate 1 conditions (once issued) bind every task; the security task lists them in the brief.

- Software members still lack a code tool until E; self-blocks from that cause will end at the head (bounded by `maxWakesPerTask`).
