## Slices

- **Slice A "core-first"**: everything that does not need a live Discord. Verified through the local CLI harness (TASK-025), which uses the same `core/interfaces.py` contracts (`ReplySink`, `SinkFactory`, `ApprovalPresenter`, `ApprovalService`, `JobRunner`, `AgentEngine`; spec §10.1) that the Discord layer implements later.
- **Slice B "Discord"**: Discord adapters and everything that needs a live server/voice. Slice B may depend on Slice A. **Slice A never depends on Slice B** (checked in the dependency table below).
- Testing and Gate 2 run after each slice (021A/022A, then 021B/022B). Docs and final sign-off (023, 024) run after both.

Splitting rule: where a task had a core part and a Discord part, `NNNA` = core (Slice A) and `NNNB` = Discord (Slice B). Core parts talk only to interfaces; no `import discord` except for `discord.Embed` as a plain data object (already in the §5.1 `ReplySink` signature).

- Thai STT below threshold or DAVE receive broken: TASK-016 blocked (B2 only); sa picks another vendor/approach; Slice A and B1 unaffected.
- Old bot and new bot answer the same message: mitigated by `CHANNEL_ALLOWLIST` (startup refusal), disjoint dev/prod allowlists and the `(ใหม่)` persona suffix; checked in 008, B1-SMOKE, B1-ENABLE.
- Shared files in B1: `core/config.py` and `core/discord/**` have one owner (008); out-of-scope changes go through PM (B.1 merge rule).
- 018B integrates with 013B's `DiscordApproverPolicy` only at wiring time; mismatch would surface in B1-SMOKE, not in unit tests.
- ffmpeg/libopus on the shared host is a host change needing owner approval (B2-PKG-SPEC).
- Webhook personas cannot be @mentioned: covered by Tier 1 name match; tested in 009.
- Slice A leaves gate, threads, buttons and voice unproven against real Discord; an interface mismatch could surface only in Slice B. Mitigation: CLI uses the same interfaces and the same engine path; 008 acceptance (4) checks it.
- CLI `--as admin` identity switch must not exist in production mode: reviewed in 022A.
- VPS runs (Py 3.12 / SQLite 3.45 vs local 3.14 / 3.53, systemd sandbox, sshd) are unverified until the Gate 2 S11 checklist is executed.
- Knowledge dir (transcripts) has no off-host backup; loss or snapshot exposure risk pending owner decision.
- Backend load concentrated in one agent: see parallelism constraint.
- Phase 2 Docker sandbox launcher (no Docker socket in bot container) is only noted in the spec here, not built.
