# REROUTE-1 — mentions of a head whose bot cannot reach the channel become tasks (spec)

Owner request 2026-11-08 (option B): in #☕-lounge (1565652686341152778) the CEO's reply mentioned @Sales and @R&D; those heads were woken in the lounge but their bots cannot access it (history 50001, replies dropped — incidents f65e8bc2, 5b244893). When a head is mentioned in a channel its bot cannot work in, turn the mention into a task in that department's own work room. Lounge stays CEO + Praw only. Requires security gate. Migration **032_reroute**. Open questions resolved with defaults (end).

## Actors / boundaries
Mentioner: head bot, persona (webhook), Praw, or human. Target: a dept head whose own Discord client cannot work in the source channel/thread. Notice poster: a bot that can reach the source. Source text untrusted; provenance rows (db/repos/botMessages.ts lookup) trusted; access check = live Discord permissions. company/router.ts route() stays pure and unchanged; all work in agents/scheduler.ts handleMessage after the guard line (`if (wr && msg.author.kind !== 'human' && (this.d.meetings?.isOpen…`) and before `for (const r of routes)`.

## Pre-conditions
`reroute.enabled` true (new key in HANDLER_KEYS, admin/keys.ts; default true; live). canRun() and not halted. Routes already admitted (admit for humans; guard checks for bots).

## A. Split — splitByAccess(msg, routes)
Only head routes with reason `mention` or `warroom` are checked (never persona_mention, reply, task_owner, dept_channel, goal_channel, direct_channel, admin_console). src = msg.threadId ?? msg.channelId. Cache miss → port.botCanWork(dept, src). Accessible → runs as today; inaccessible → moved[]. reroute.enabled off → moved routes dropped (no run), one warn per (dept, src). Then `void this.spawn('reroute', () => this.reroute(msg, moved))`.

## B. DiscordPort.botCanWork(dept, id): Promise<boolean> (discord/port.ts, next to canStartThread; clientOf(dept), members.me)
False on: bad snowflake; isExcludedChannel; client offline; channels.fetch throws (50001, 10003, anything). Text channel needs ViewChannel + SendMessages + ReadMessageHistory. Thread: permissionsFor(me) (parent perms) needs ViewChannel + ReadMessageHistory + SendMessagesInThreads; locked/archived without ManageThreads → false; private thread needs membership (members.fetch(me.id) resolves) or ManageThreads. Any throw → false (fail-closed).
Scheduler AccessCache: definite answers only, TTL 60 s, ≤1000 entries; transient errors (not 50001/50013/10003) not cached; cleared on /resume.

## C. reroute(msg, moved) — per dept in route order; ≤3 per message for humans (bots already capped 3, CEO 5 via WARROOM_MENTION_CAP*)
1. Halt check: halted or !canRun() → return.
2. Mentioner & taint. Bot author (msg.author.actor): read provenance row of msg.id, poll up to 6 × 500 ms (post() records in onSent; record can land after the gateway echo); tainted = msg.forward || !row || row.tainted; triggerUserId = row?.userId ?? null. Human: tainted = runStartsTainted({msg, task: threadTask, history}, lookup) with history read by the notice poster; failed read → tainted = true.
3. Authorisation (no widening; each failure = refusal with fixed reason): Bot → org.canDelegate(mentioner, {kind:'head', dept}) (persona reaches only its own head). Praw mentioner → also canMemberView(triggerUserId, target.workChannelId); null user = refusal. Human → canMemberView(msg.author.id, target.workChannelId), fail-closed, no warroom fallback. Target dept enabled, online, has workChannelId (Praw has none → never rerouted). Chain check: refuse if dept in chainDepts(parent) (lift chainDepts from tools/builtin/forwardTo.ts into company/forward.ts).
4. Parent (bots only), under `this.locks.run(parent.id)` while choosing and creating the child (CEO's run holds the conversation lock until conv.release):
   (a) source thread with a task whose owner is the mentioner → that task.
   (b) top-level source and triggerUserId set → tasks.findOpenConversation({deptId: mentioner.dept, userId, where: msg.channelId}); inside the lock re-read status, accept only doing/review; else adopt a new conversation via new conversation.adopt({actor: mentioner, userId, channelId, originMessageId, tainted, categoryId}) — status doing, threadId = channelId (top-level), conversation true, origin chat, originMessageId = msg.replied?.id only when msg.replied.author.id === userId else null. After the child exists call this.afterRun(conv) (→ review). Never update originMessageId of an existing conversation. Never attach to a done/cancelled parent (rules out silent NO_ROLLUP loss in reportEnded).
   (c) otherwise no parent: take this.d.agent.botRoots.acquire() (TW6 daily cap); null = refusal.
   Human mentioner: no parent; child is a root task, requester {kind:'human', userId}, origin chat.
5. Limits via this.d.agent.limits: checkDepth(parent.depth), checkChildren(parent.id), checkOpenTasks(). Per-root cap shared with forwards: tasks.takeForward(rootId, FORWARDS_PER_ROOT) on the parent's root (new root needs no slot). Duplicate guard: skip when parent already has an open child owned by dept created within 15 min (covers mentioner's own create_task in the same run).
6. Child task: title = rerouteTitle(from) → `Rerouted mention (from <deptId|member>)` (fixed, code-made). description = rerouteDescription({link: discordLink(guildId, src, msg.id), from, quote: cleanCardText(msg.content, 1500, secrets)}) (first line = source line so cardBody works). forwardCard: 'link' unless source is public (channelIsPublic, thread-aware as G2RF-02) or source is the target room → 'full'. owner {kind:'head', dept}; requester = mentioner (bot) or human; origin 'delegated' (bot) / 'chat' (human root); status todo; estCostUsd 0; tainted per step 2; rerouteSourceId = msg.id. channelId = target.workChannelId if canStartThread(dept, it); else bots only AI_WARROOM_CHANNEL_ID; else refuse. Never homeChannel/placeInOrigin (would search the HQ category incl. lounge). 23505 unique violation = duplicate: skip, no notice. Then bus.emit('task.created').
7. Notice (in-memory map taskId → {source, poster, replyToId: msg.id}, ≤200 entries, lost on restart), posted from handleCreated after ensureThread. Skipped when H1 will run (parent has thread, not top-level, TEAMTALK on). Poster: the mentioning bot; for a human mentioner the first of [deptOfChannel(src) head, hq, praw] passing botCanWork, none → log only. Payload {type:'chat', body, noHandles:true}, reply to msg.id; provenance answer=false, tainted = child.tainted, userId = triggerUserId. Always a new post, never edits a STREAM-1 preview. Body: `➜ ส่งต่อให้ ${deptName} ในห้องงานของแผนก: ${discordLink(guild, workChannel, threadId)}`; off day when tree held adds ` (เริ่มวันทำงานถัดไป)`. Refusal: `➜ ส่งต่อให้ ${deptName} ไม่ได้: ${REASON[code]}` (fixed Thai map; codes no_access, not_allowed, limit, chain, no_room, disabled); ≤1 refusal per (src, dept) per 10 min.

## D. Result
Thread parent: normal H1, H3, roll-up. Top-level conversation (lounge): H1 skipped (postHandoff isTopLevelConversation), H3 quiet for done (reportEnded quiet), noteReport keeps the report (headConv), rollUp makes the CEO reply in the lounge to originMessageId; cancelled/blocked children still post a "Subtask …" line in the lounge as the CEO. Human root: head answers in the dept thread, no relay back (notice link only). No parent (bot talk): result stays in the dept thread.

## E. Interplay
Off day: delegated child → treeHeld → noteHeld (OFFDAY-1) + OT card (OT-1); human root is human-origin and runs. SPEND-1 dept caps/budget at run time; reroute itself $0, no model call. Tainted child → per-tool approvals + batching as usual; no estimate approval (estimate 0). Loops: no bot turn in the source; chain check, depth, children, takeForward, botRoots bound the rest; guard pause/stall already empty routes upstream. TEAMTALK defangHandles + noHandles on every post; card text via cardBody.

## Security (Gate 1)
No widening: each mentioner class gated exactly as its existing tasking power (canDelegate; P16d member view for Praw; member view for humans; persona → own head only); foreign/unattributed bots dropped by the router. Injection: title/thread name fixed code text; quote via cleanCardText (zero-width, NFKC, redact, neutralise, ≤1500); taint from DB row, unknown row = tainted; model reads quote inside the untrusted wrapper. Privacy: RF11 forwardCard 'link' hides the quote on cards in wider rooms; residual R-1 (owner run may repeat lounge text in the dept room); never include the replied-to (owner's) message. Spam: per message 3 (CEO 5); takeForward per root 4; botRoots daily cap; open-task cap; human rate slot already taken; refusal notices 1/10 min per (src, dept); unique index (source, dept). Logs: dept, channel id, msg.id, reason code only.
